# Terrarium audit — 2026-07-15

Scope: the git-tracked modular tree (`src/`, CMake project 0.70.05) plus a
comparison against the `terrarium_remix_0.70.05.cpp` monolith. Findings that
were fixed the same day are marked ✅ (see CHANGES.md).

## Headline finding: two divergent "latest versions"

The git history is:

1. `338a3b0` (Feb 23) — baseline: a 5283-line `terrarium.cpp`
2. `72d23cd` (Mar 27-28) — that baseline modularized into `src/`

But remix development continued in untracked monoliths until
`terrarium_remix_0.70.05.cpp` (Mar 27, 5723 lines). The modular tree is a
clean-up of a **month-older** program. Everything the remix line gained is
absent from `src/`:

- Rich ecosystem: `SpeciesDef` table, per-biome species pools, detritus +
  fertility fields, habitat suitability, aging (`age`/`maxAge`), immigration,
  eco events (upwellings, blooms), float water depths.
- Audio robustness: `pw_init()` before FluidSynth's pipewire driver ✅
  (restored), single-thread-when-synth rule, audio watchdog/reset,
  removal of `synth.chorus.type` ✅ (restored).
- The Wii-soundfont-era tuning (reverb/chorus values survived; the
  polyphony/period settings did too).

**Resolved 2026-07-16**: the fork was intentional — the owner was unhappy with
the late remix versions and deliberately continued from the older baseline.
The modular tree is canonical; the remix monoliths are reference only.

## Performance (measured, i5-5257U)

- gprof: `stepTerrain` = 87% of `step()` — 12 `countNeighborsChar` calls per
  cell. ✅ Single-pass neighbor bucketing + fire-scan gate: 12→5 ms/tick at
  200x200. `stepWater` (15%) and `waterSinks` (9%) are the remaining costs.
- mt19937 + per-call distributions replaced with xorshift64* ✅.
- Main app rendered ~150 fps of full-glyph passes for a 6 TPS sim ✅ (60 fps
  cap). Still heavy (~45k SDL calls/frame): dirty-cell tracking or a single
  streaming-texture path (like pico) would cut most of the remainder.

## Design smells (noted, not changed)

- Per-agent O(N²) proximity loops (parasite/swarmer/packhunter, predator
  distance) — fine at ≤~130 agents, will not scale past a few hundred.
- `s_prevPos` in `computeViewAudioMetrics` keys agent history by vector
  index; indices shift when agents die (wrong speed attribution for a tick).
- Voice-0 program cache vs auto instrument changes can disagree (both write
  channel 0's program with separate caches).
- Menu `menuSel` is shared across pages; per-page clamping saves it, but a
  page switch can leave a stale selection row highlighted.
- `fgForChar` paints agent sprite glyphs (0x80+) plain white — species are
  visually indistinguishable in color.
- Layout.scale is a constant 2 — text/UI doesn't scale with resolution.

## Raspberry Pi Zero verdict

**The desktop app will not run acceptably on a Pi Zero** (1 GHz single-core
ARM11, 512 MB): measured ~60-75% of an i5-5257U core, dominated by the
per-cell glyph renderer; ARM11 is roughly 15-25x slower single-thread, so
the render alone is ~10x over budget. RAM is fine (20 MB + a 17.7 MB
soundfont), CPU is the wall. FluidSynth with reverb+chorus at 48 kHz is also
marginal-to-infeasible on ARM11.

**The new `terrarium-pico` target is the answer**: 200x200 world rendered as
one pixel per cell into one streaming texture, redrawn only on sim ticks,
no audio. Post-optimization sim cost is ~5 ms/tick here → ~75-125 ms/tick
estimated on ARM11 → comfortable at 4 TPS (`--tps 4 --scale 1`), and easy
for a Pi Zero 2. Build on the Pi:

```
sudo apt install -y cmake g++ libsdl2-dev
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --target terrarium-pico
./build/terrarium-pico --scale 1 --tps 4
```

(Unverified on real hardware — estimates from single-thread scaling.)
